# HandMotion: 複数視点の校正3D統合

対象: 同じ片手を、1台のPCにつないだ2〜3台の通常カメラで観察する研究開発版。映像・座標はブラウザ内で処理します。録画は行いません。既存の単眼画面と個別録画画面は残しています。

**現在の状態**: OpenCV.js 4.11.0を許可に基づき同梱しました。校正板の生成・検出、内部校正、共通座標の推定、複数視点3D統合を合成データで検証しています。実カメラの精度・同時露光・手袋条件の性能は未検証です。研究用の高精度計測として認定したものではありません。

## 何が変わるか

各カメラで独立したMediaPipe Hand Landmarkerを動かし、元画像上の同じ関節の2D位置を使います。共通校正したレンズ・位置・姿勢から、複数の視線が交わる位置を計算し、校正板を基準にしたXYZ（mm）を表示します。単眼のworldLandmarksを回転・平均する方法ではありません。

**MediaPipeのモデル自体は変更・追加学習していません。** 複数視点の幾何と不整合除外を追加したもので、手袋・反射・接触時の認識精度が上がったと実証したわけではありません。単眼の相対3Dより尺度を定義しやすくなりますが、実測精度はカメラ・校正・同期・2D誤差に依存します。

## 起動

共有版のURLは https://daijirohaba.github.io/mediapipe-hand-motion/fusion.html です。公開元のPC起動は不要です。ローカル開発版はアプリルートのstart_app.cmdを起動し、画面上部の「校正3D統合」へ進みます。通常URLは http://localhost:8793/fusion.html です。別ポートを使用した場合は起動ログのURLを使います。

## 初回の流れ

撮影配置の図と印刷物は作成済みです。アプリの「図で見る撮影・校正」から開けます。

- camera_setup_20261005/guide.html: 図付きの操作ガイド。
- camera_setup_20261005/CAMERA_SETUP_GUIDE_JA.pdf: 3ページの説明書。
- camera_setup_20261005/CHARUCO_A4_25mm.pdf: A4・1ページの実寸校正板。印刷倍率100%で使用。
- camera_setup_20261005/camera_setup.png: PC内蔵カメラとUSBカメラの配置イメージ。

校正板の模様を自作する必要はありません。PDFを印刷して硬い平板へ貼り、マス25mm・確認線100mmを実測します。配置図はAI生成の説明画像で、図中の模様を校正に使いません。

1. **カメラ配置**: 片手が両方から大きく見えるよう、左右斜めから固定。厳密に矢状面・前額面へ合わせる必要はありません。似た方向からの2台は奥行きに弱くなります。内蔵カメラならPCのふたも固定します。
2. **機器確認**: カメラA/B（必要ならC）で異なるデバイスを選び、実際の映像・名前・解像度を確認。「映像・手指推定を開始」で各映像に手指点が出ます。この段階では共通3Dを表示しません。
3. **校正板**: 「作成済みの校正板PDFをダウンロード」でChArUco（6×8、DICT_4X4_50、正方形25 mm、マーカー17.5 mm）を100%印刷。定規で正方形の寸法を実測し、剛体平板に貼ります。印刷倍率の誤りはそのまま3Dの尺度誤差になります。画面に映した板は精密計測用に使いません。
4. **内部校正**: 板の上下左右、距離、傾きを変えて12〜30組を追加します。ボタンを押す際は板を静止。約400 ms離した2回の検出で1 px以上動いた組や12点未満の組は拒否します。これだけで完全な静止を証明するものではありません。
5. **計算**: 「内部校正を計算」。各カメラの焦点距離・主点・Brown-Conrady歪み5係数（k3固定）をOpenCVで推定します。計算はWorker内です。内部RMS 1.5 px以下、板の位置範囲・傾き幅の条件を満たさなければ再取得します。
6. **共通原点**: 内部校正に使った取得とは別に、同じ静止板を全カメラに同時に映し「共通原点を設定」。各カメラのboard-to-cameraのR,tを求めます。校正板左上を基準とするX・Yと右手系のZを使い、身体の左右・上下とは同一視しません。板の置き方によってZの見え方は変わります。
7. **保存**: 校正JSONを保存。板を除き、カメラを動かさず、同じ片手を映します。カメラ配置不変と「同期未検証の探索表示」にチェックすると、条件を満たす点だけ3D表示します。
8. **観察**: XYZは校正板原点からの座標。「中央へ」で手指を表示中心へ移動できますが、座標原点は変えません。ドラッグで360度回転、ホイールで拡大縮小、全画面に対応。全関節が表示されないのはQCで欠測になった可能性があります。

校正板の印刷はカメラ開始前に済ませるとスムーズです。プライバシー保護のため、別タブへ移るとカメラは停止します。再開始すると収集中の校正画像はリセットされます。内部校正のためにカメラを動かすのではなく、固定カメラの前で板を動かしてください。

焦点・自動ズーム・電子手ぶれ補正・解像度・デジタルクロップを固定してください。ブラウザから制御できない機器設定は機器側で管理し、固定できない場合は精密計測に使いません。カメラ移動、PCのふたの角度、解像度変更後は再校正。機器IDのハッシュと実解像度が校正と合わない場合は統合を停止します。ブラウザ・公開URLを変えると機器IDが変わる場合があり、その場合も再校正します。

## 採用・欠測のルール

- 同じ片手を写すことが前提。各視点で0手または2手なら、その視点は融合しません。左右分類だけで人物・手を識別しません。
- 2視点以上の時刻が近い結果を選択。既定50 ms、選択肢20/35/50 msは**表示処理時刻差**です。露光時刻差ではありません。
- 750 msより古い観測を採用せず、3Dの古い表示も隠します。撮影と推定は別速度です。
- 時刻条件内では使用視点数を優先するため、新しい2視点組より少し古い3視点組を採用することがあります。最大750 msの取得側制約内ですが、低遅延を保証しません。
- 歪み補正が収束しない点、画像外、カメラ後方の解、交差角3度未満、不安定な幾何、再投影誤差2.5 px超などを欠測にします。
- 3台の場合は2台の候補から整合する視点を集め、視線の最小二乗で再計算。不採用視点も保存します。
- これらの閾値は試作の工学的QC設定であり、研究の妥当性基準や1 mm精度の保証ではありません。
- 2視点で整合して見える誤対応や、複数視点で共通したモデル誤推定は除外できない場合があります。MediaPipeが見えない指先も推測するため、「有効」は直接観測の保証ではありません。
- 補間、単眼3Dによる欠測穴埋め、圧から奥行きへの変換は行いません。
- 正規化座標からの画素変換はu=x×幅、v=y×高さです。MediaPipeとOpenCVの画素中心規約の半画素程度の差は独立に未検証です。推測だけで0.5 pxを差し引かず、この規約をmanifest/生成校正JSONへ記録します。サブピクセル精度を論じる前に、実標的で系統差を確認してください。

## 同期と押し込み量の限界

ライブでも、普通のUSB/内蔵カメラは同時露光を保証しません。本版は表示時刻で対応を選ぶ探索表示です。出力はGEOMETRIC_ESTIMATE_SYNC_UNVERIFIEDとし、時間補正や検証済み同期を名乗りません。captureTimeは取得できた場合だけ元の値を保持し、異なるカメラ間で同じ露光時計として扱いません。

動的な実寸計測を成立させる次工程は、共通の光学イベントを使った時刻対応と不確かさの評価、またはハードウェア同期カメラです。指先速度が100 mm/sなら、10 msで1 mm動きます。この概算に加えて視線角度やローリングシャッターの誤差もあります。

XYZの変化は、真の「押し込み量」とは別です。接触する指腹が隠れ、手袋が滑り、対象全体が動く場合、骨格指先の移動をそのまま押し込み量にしません。圧機器との統合は機器仕様・時刻・部位・単位が確認できてから別工程で行います。

## 精度を確立するための実機確認

校正に使っていない剛体の既知長さ・既知変位を、測定予定の領域・距離で再構成してください。静止時の揺れだけでなく、真値からの偏り、奥行き位置による違い、再設置、移動速度、素手/手袋、反射/遮蔽の条件別欠測を確認します。再投影誤差だけでは実寸精度を認定しません。

まずは静止標的、次に非人物の既知変位、最後に手指動作の順です。必要な精度の合格基準と参照機器は研究者が事前に決めてください。本版の実機精度は未認定です。

## ZIPの構成

- coordinates/2d_A.csv 等: 各視点の元画像正規化座標、モデル相対z、フレーム識別子・時刻。モデル相対zとmmのZは別列です。
- coordinates/fused_3d.csv: 共通XYZ(mm)、使用/除外視点、再投影誤差、交差角、時刻差、欠測理由。数値不採用時は空欄。
- reports/fusion_qc.json: 統合ごとのQCと、実際に参照した2D座標・時刻のスナップショット。
- calibration.json: 保存時の校正。calibrations/: 取得中に使用した校正IDごとの値（途中で校正を変えても旧値を保持）。
- manifest.json、README_RESULTS_ja.txt: 条件と制約。動画は入りません。

CSVはUTF-8 BOM付き。座標記録は明示ON、各カメラ最大1,000推定、融合最大1,000組です。録画していなくても座標を保存する場合があるため、同意と保存先の管理が必要です。ダウンロード先がOneDriveの場合はその同期設定が別途適用されます。

## 手法の根拠

- OpenCVカメラ校正、歪み、R,t、再投影: https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html
- ChArUcoの点IDと校正板: https://docs.opencv.org/4.11.0/df/d4a/tutorial_charuco_detection.html
- MediaPipe Hand Landmarker（2D/モデル相対3D）: https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js

校正とPnPにはOpenCV.js、最小二乗視線交点の3×3行列演算と描画には同梱Three.jsを使用します。OpenCVのtriangulatePointsを使用したと偽称しません。部分的な外れ値除外と採否処理は本アプリの実装で、合成テストとコード監査の対象です。

## 依存ライブラリとセキュリティ

OpenCV.jsは公開パッケージ @techstark/opencv-js@4.11.0-release.1 の固定版を取得し、実行時のOpenCV 4.11.0を確認しました。OpenCV公式サイトの直接取得が制限されたため、jsDelivr上の同パッケージを利用しています。配布元・サイズ・SHA-256はvendor/OPENCV_DEPENDENCY.json、ライセンスはvendor/OPENCV_4_11_LICENSEに保存しています。第三者の配布パッケージであり、本アプリ独自のOpenCVビルドではありません。

この版のEmbind初期化にはJavaScriptの動的関数生成が必要なため、校正3DページのCSPではunsafe-evalを許可しています。スクリプト・通信の取得元は同一オリジンに制限し、外部スクリプトの読込み、映像アップロードは実装していません。公開時にホスティング側でより厳しいCSPを追加すると校正が起動しない場合があります。既存の単眼・個別録画ページの設定は変更していません。
